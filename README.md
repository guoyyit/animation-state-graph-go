# animation-state-graph-go

动画状态图运行时：在同一进程内为大量实体按外部参数驱动状态切换，
并对多个动画片段做加权混合。核心目标：**并发安全、结果可复现、支持图定义热更新**。

```go
rt, _ := anim.NewRuntime(def)          // 编译并校验图定义
e := rt.Spawn("npc-1")                 // 创建实体（从入口状态开始）
e.SetParams(anim.NewParams().SetFloat("speed", 3.0))
frame := e.Advance(0.016)              // 推进一帧，返回加权混合输出
snap := e.Save()                       // 可持久化快照
```

## 状态机语义

- 图由 **状态（State）**、**转移（Transition）**、**混合节点（BlendNode）**、**参数（Param）** 组成。
  实体从 `Entry` 指定的入口状态开始。
- 每帧推进（`Advance(dt)`）语义：
  1. 帧开始时读取一次图指针，本帧内使用同一图快照（热更新不会读到半更新状态）。
  2. 仅当不在过渡中时，评估**当前状态**的出边条件（O(出边数)，不扫描全图）。
  3. 转移发生时切换当前状态；若 `Duration > 0` 进入交叉淡入过渡态，
     过渡期间输出为源/目标状态混合结果的插值。
- **同帧多转移同时满足的裁决规则（确定性）**：
  按 `(Priority 升序, 定义顺序升序)` 取第一个条件满足者。
  该排序在编译期完成，与遍历顺序、运行时随机化无关。
- **自我转移与环状转移**：每帧每个实体**最多发生一次转移**。
  自我转移只重置状态计时、不进入过渡态；环状转移（A→B→A）在后续帧逐跳推进。
  两者都不会死循环，也不会同帧重复进入同一状态。
- 转移条件中参数缺失或类型不匹配时，条件按 **false** 处理（不转移），
  并产生可定位诊断（见下文），不会静默放行。

## 混合规则

- 混合节点对若干 `ClipRef` 加权混合。权重来源：
  `Param` 非空时取该 Float 参数的当前值，否则取 `ConstWeight`。
- 负权重钳制为 0；所有有效权重**归一化**（输出权重和恒为 1）。
- 权重参数缺失/类型不匹配时，该片段权重降级为 0（退出本次混合）并记录诊断。
- 全部权重为 0 时，回退为第一个片段权重 1（确定性兜底，避免输出空洞）。
- 过渡期间输出为 `lerp(源状态混合, 目标状态混合, t/Duration)`，
  两侧各自归一化后再插值，因此**任意时刻权重和为 1，权重随时间连续变化，
  无突变、无跳变**（测试 `TestBlendNormalizationAndSmoothTransition` 逐帧验证）。

## 参数配置与异常策略

参数在 `GraphDef.Params` 中声明：`Name`、`Type`（Float/Bool/Int）、`Min`/`Max`
（仅数值类型；`Min >= Max` 视为不约束）。

| 异常 | 策略 | 诊断 Code | 级别 |
|---|---|---|---|
| 参数缺失 | 条件按 false；混合权重降级为 0 | `param.missing` | Error |
| 类型不匹配 | 同上 | `param.type` | Error |
| 取值越界 | 钳制到 [Min, Max] 后继续使用 | `param.range` | Warn |

每条 `Diagnostic` 携带 `Binding` 字段（如 `blend/moveBlend/clips[0]`、
`state/idle/trans[1]`），可定位到具体绑定；不会静默放行。

## 热更新

`Runtime.Update(def)` 先完整编译校验新定义：

- **校验失败**：返回错误，保留上一个可用定义继续运行，实体不受影响。
- **校验成功**：通过原子指针整体替换。推进中的实体在帧开始时读取一次指针，
  本帧内始终看到完整的旧定义或完整的新定义，**不会读到半更新状态**。
- 更新后若实体当前状态在新图中不存在，重置到入口状态并产生
  `state.missing` 诊断（文档化降级策略）。

## 并发模型

- `Graph` 编译后不可变，可被任意多实体并发读取，无锁。
- 每个 `Entity` 持有独立的参数与内部状态，由各自的互斥锁保护；
  实体之间零共享，互不串扰，慢实体不阻塞其他实体。
- `Runtime.AdvanceAll` 并发推进一批实体：单实体的 panic 被隔离为诊断，
  不拖垮整体；返回结果顺序与输入顺序一致，与并发度无关。

## 可复现性

- 固定参数序列下，多次运行与不同并发度（1/4/16/64）的输出**逐条一致**
  （`TestConcurrentAdvanceDeterministic` 验证）。实现上：
  无 map 遍历参与输出、无全局随机源、裁决与合并顺序全部在编译期固定。
- `Entity.Save()` 产生**字节级可复现**的快照（map 键排序后编码）；
  `Runtime.Restore()` 校验图版本一致且状态存在后才恢复，
  恢复后继续推进的输出与不重启逐条一致
  （`TestSaveRestoreReproducible` 验证）。版本不一致时拒绝恢复。

## 性能

单帧推进复杂度为 **O(当前状态出边数 + 当前混合节点片段数)**，
与图中状态总数、实体总数无关：

- 编译期建立状态/混合节点/参数索引，转移按裁决顺序预排序；
- 推进时只访问当前状态的出边与当前混合节点，不扫描全图；
- 单帧内存分配仅为输出切片与诊断切片。

基准（`BenchmarkAdvanceScalesWithGraphSize`，Xeon 8255C）：

| 状态数 | 单帧耗时 |
|---|---|
| 100 | ~720 ns |
| 1 000 | ~860 ns |
| 10 000 | ~1 135 ns |

状态数增长 100 倍，单帧耗时基本持平（残余差异来自缓存效应而非算法复杂度）。
因此单实体单帧耗时上界由**当前状态的出边数与片段数**决定，
万级状态图下单帧仍在微秒级。
